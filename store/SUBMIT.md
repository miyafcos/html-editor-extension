> **注意:** PowerShell 5.1 の `Compress-Archive` はパス区切りに `\` を使う。
> Chrome Web Store はこれを読めないため、再作成するときは
> `scripts/mkzip.py`（`zipfile` + `as_posix()`）を使うこと。

再ビルドから作り直す場合:

```
npm run build
python scripts/mkzip.py
```

`manifest.json` がルートにあることと、区切りが `/` であることを自分で検証してから
終了する。

## スクリーンショットの再生成

```
npm run build
node scripts/shots.mjs
```

使い捨てプロファイルの Chrome をヘッドレスで起動し、ダミーデータとブックマークを
投入して5枚撮る。宮崎さんの実プロファイルには接続しないので、実案件が写り込む
経路がない。

注意点（いずれも実際に踏んだもの）:

- **ヘッドレスを外さない。** ウィンドウが前面に出ると、操作者が打ったキーが
  新しいタブの検索ボックス（自動フォーカス）に入り、カタログが絞り込まれた状態で
  撮れる。エラーは出ないので気づきにくい。
- ファビコンは Chrome のファビコンDBから引くため、撮影前に各URLを訪問して
  キャッシュを埋めている。この処理は storage 投入より前に走らせること
  （後だと service worker が訪問を記録してカタログを上書きする）。
- 撮影後は5枚を必ず目視する。サイズが 1280×800 でも、レイアウト崩れや
  読み込み途中の状態は機械チェックを通過する。

## 手順

### Step 1 — デベロッパー登録（$5・一回限り）

1. https://chrome.google.com/webstore/devconsole/ を開く
2. 登録に使う Google アカウントでログイン
3. 利用規約に同意 → **登録料 US$5 を支払う**（買い切り。以後何個公開しても追加費用なし）
4. 連絡先メールアドレスを登録し、**検証メールのリンクを踏む**
   （検証が済むまでアイテムを公開できない）

### Step 2 — アイテムを作成して zip をアップロード

1. ダッシュボードで **「新しいアイテム」**
2. `HTMLHub_v0.15.1_20260901.zip` をアップロード
3. アップロードが通れば manifest は問題なし。ここで弾かれる場合は zip の作り方を疑う

### Step 3 — Store listing（掲載情報）

`store/listing-ja.md` の内容をそのまま貼る。

- 短い説明 / 詳細説明
- カテゴリ: ワークフローと計画
- 言語: 日本語
- アイコン 128×128: `public/icons/icon-128.png`（アップロード済みパッケージから自動取得される）
- **スクリーンショット** — `store/screenshots/` の5枚をアップロードする:
  - `01-catalog.png` 新しいタブのカタログ全体
  - `02-search.png` 検索での絞り込み
  - `03-preview.png` ホバープレビュー
  - `04-dashboard.png` ダッシュボード
  - `05-editor.png` その場編集

### Step 4 — Privacy practices（プライバシー）

`store/justifications.md` の内容をそのまま貼る。ここが審査の本体。

1. **単一目的の説明** — 「Single purpose description」の段落
2. **各 permission の justification** — 13 個 + host permission。全欄を埋める（空欄があると差し戻し）
3. **データ利用の申告** — 「Web history」と「Website content」に Yes、他は No
4. **3 つの誓約にチェック**
5. **プライバシーポリシー URL** を入力（上の「1 について」で決めたもの）

### Step 5 — Distribution（公開範囲）

**一般公開（Public）を選ぶ**（2026-09-01 決定）。検索に出る。単一目的ポリシーの審査が
一番厳しい枠なので、`store/justifications.md` の Single purpose description をそのまま
使うこと。

（参考: 限定公開 = 検索に出ず URL を知る人だけ / 非公開 = 指定アカウントのみ）

対象地域は「すべての地域」で問題ない。

### Step 6 — 提出

「審査のために送信」を押す。

## 審査について

- **所要**: 数時間〜数日。permission が多い拡張は長めに出る
- **この拡張が見られるポイント**:
  - 新しいタブページの置換 → 検索エンジンを変えていないこと（`chrome.search.query()` の委譲）を justification で明示済み
  - `history` / `bookmarks` / `<all_urls>` → 全部ローカル完結であることを明示済み
  - 単一目的 → 「ローカル HTML 文書のワークスペース」で統一済み
- **差し戻された場合**: 理由がメールで届く。文面をこのファイルに追記してから直す

## 公開後

- 更新は `manifest.config.ts` のバージョンを上げて再ビルド → 新しい zip をアップロード → 再審査
- バージョンは前回より必ず大きい必要がある（`0.15.1` → `0.15.2`）
